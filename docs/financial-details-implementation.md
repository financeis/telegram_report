# 금융 정보 구조 확장

## 범위

기존 LLM 분석 카드에 실적 전망, 밸류에이션, 투자 논리·촉매, 보고서 비교를 추가했다.
수집기·태깅·OCR·KRX 기준표·퀀트 신호·백테스트는 변경하지 않았다.
기존 요약 테이블에 기능 저장용 nullable JSONB 필드 두 개만 추가했다.

## 사용 방법

> 아래는 Streamlit 대시보드 시절의 사용법이다. 그 대시보드는 삭제됐고, 같은 정보는
> Research Desk의 리포트 상세·비교 화면에서 본다 ([research-workspace.md](research-workspace.md)).

1. 분석 대시보드에서 종목을 검색한다.
2. `🤖 LLM 분석` 탭에서 자료가 있는 기간을 선택한다.
3. 새 보고서는 `🤖 LLM 분석`으로 생성한다.
4. 기존 기본 요약은 `금융 정보 확장 (기존 N건)`으로 확장한다. 선택한 기간의 기본 요약과 미분석 보고서가 대상이며, 이미 확장된 요약은 재사용한다.
5. 요약 카드를 펼치면 네 개의 금융 정보 탭이 나온다.

2026-09-15 현재 시연은 `016360 삼성증권`의 6개월 기간에서 볼 수 있다.
2026-05-11 보고서는 2026-02-09 KB증권 보고서와 비교한다. 이전 문서가 현재 조회 기간 밖이어도 저장된 분석으로 비교할 수 있다.

## 각 영역

- 실적 전망: 지표, 대상 회계기간, 실적/추정/가이던스, 연결/별도, 시나리오, 단위, 수치와 이전 추정. 수치별 원문 페이지와 인용을 제공한다.
- 밸류에이션: PER/PBR/DCF/SOTP 등 평가방식, 가정, 변경 전후 값, 목표주가 변경 이유. 원문 추천등급과 증권사 정의를 보존한다.
- 투자 논리·촉매: 주장, 원인→결과 경로, 사실/가이던스/추정/의견 구분, 확인할 지표, 가설 재검토 조건, 예상 촉매와 시기. 재검토 조건이 명시된 것인지 논리에서 도출한 것인지 표시한다.
- 보고서 비교: 동일 발행처의 변화와 다른 발행처의 의견 차이를 구분한다. 수치 표는 기간·단위·통화·회계기준·실적/추정·시나리오가 같은 항목만 비교한다.

## 숫자 처리

- 이전 추정은 문서에 명시된 같은 기간의 수정 전 값이다. 전년 실적과 비교하지 않는다.
- 현재 값과 이전 값이 원문 인용과 해당 PDF 페이지에 실제로 존재하는지 확인한다.
- 문서 내 수정 전후 값은 같은 수정 근거에 두 숫자가 함께 있어야 채택한다.
- 연간 BPS와 12M forward BVPS를 섞는 명확한 사례는 비교에서 제외한다.
- 평가기간 변경 이유는 이전/현재 기준이 모두 있어야 채택한다.
- 이익률·ROE는 %p, 흑자/적자 전환은 별도 표시한다. 0 또는 음수에서 일반 증감률을 만들지 않는다.
- 근거 확인에 실패한 수치는 제외하고 제외 개수를 보여준다.

이 검증이 표의 행·열 해석과 회계 의미를 모두 보장하는 것은 아니다. 원문이 불명확하거나 표 간 명칭이 충돌하면 일부 값이 비거나 검토가 필요하다. 비교 대상은 기존에 저장된 분석이며 시장 전체 컨센서스나 공시 실적 대조 기능은 포함하지 않는다.

## 변경과 배포

- `migrations/006_financial_details.sql`: `financial_details`, `comparison_details` 추가. 현재 연결된 Supabase에 적용·컬럼 확인 완료.
- `financials.py`: 타입 정의, 수치 근거 확인, 비교 산술.
- `schemas.py`, `prompts.py`: 금융 구조 추출을 기존 OpenAI 호출에 포함.
- `pipeline.py`, `summary_store.py`: 기본 요약 확장, 금융 정보 저장, 비교 데이터 전달/저장.
- `financial_view.py`, `tab.py`: 네 영역 및 기존 요약 확장 버튼.

기본 요약 버전은 그대로 유지한다. 기존 기본 요약을 한꺼번에 재처리하지 않으며 명시적 확장 버튼으로 처리한다.
