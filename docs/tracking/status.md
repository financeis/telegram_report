## 남은 것 (먼저 할 것부터)

1. **운영 따라잡기.** 수집이 9월 초 메시지에서 멈춰 있다 → `python -m research_desk collect`로 따라잡는다. 그 사이 빠진 번호가 있는지는 `collect --dry-run --backfill-days N`으로 본다. 그다음 쌓인 분류 대기를 `powershell -File scripts\run-batches.ps1 -Iterations N -BatchSize 10`으로 처리한다 — 새 명령 체계로 하는 첫 실운영이므로 첫 몇 배치의 JSON 보고와 `tag inspect` 비율을 확인하고, Haiku 5.5의 배치 소요 시간을 다시 잰다.
2. **웹앱 실제 실행.** `powershell -File scripts\start-workspace.ps1`(또는 `python -m research_desk web`)로 다시 켜서 화면 전체를 한 번 써 본다.
3. **화면 코드 분할(다음 차례).** `frontend/`는 한 파일에 거의 모든 화면이 들어 있다. 메뉴·화면 전환 틀 / 공용 부품 / 기능별 폴더로 나누고, 한 기능의 서버 폴더와 화면 폴더 이름을 맞춘다. 화면 주소의 보기 이름(`?view=market` 등)과 서버 주소(`/api/market`)는 호환을 위해 둔다. 화면 쪽에 따로 복사된 분석 대상 외 사유 목록을 공용 기준(`domain/vocabulary.yaml`)과 맞춘다. 분할 전후 화면이 같은지 캡처로 비교한다. 화면 폴더의 작업 안내도 이때 만든다.
4. **수급 데이터 분석, 기업간 유사도 분석.** 각각 외부 데이터 받기, 자기 표, 계산, 화면으로 붙는 새 기능 폴더. 데이터 출처(증권사 API 등)와 유사도 기준은 붙일 때 정한다.
5. **퀀트 연결.** 주가·공시 데이터를 붙여 리포트의 전망 변화와 실제 주가·실적을 비교·검증한다. 당시 쓸 수 있었던 정보만 쓰는 시점 규칙이 핵심이다. 여러 기능이 같이 쓸 주가 데이터는 기능 하나가 주인이 된다.
6. **종목표 자동 갱신.** API로 종목표를 받아 CSV와 버전 정보를 함께 쓴다(`domain` 자리). 날짜별 보관(상장·폐지 이력)은 퀀트 연결과 함께 정한다.
7. **예약 작업의 실패 알림.** 첫 예약 작업(윈도우 작업 스케줄러)을 붙일 때 정한다. "잘 돌고 있나"를 한눈에 보는 것이 목표다.
8. **다른 기기 접속(시점 미정).** 이 PC가 계속 서버가 될지 클라우드로 옮길지 미정이다. 접근 제어는 웹 조립부 한 곳에 붙인다.
9. **그 밖의 기능.** 계속 붙일 예정이고, 무엇을 언제 붙일지는 미정이다.
