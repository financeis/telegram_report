# 0008 — 재무 분석·비교 모델은 `codex:gpt-6-luna`, Claude에서는 형식 강제 없이 검증

## 배경
웹앱의 리포트 1건 재무 분석과 비교 해석문에 쓸 모델을 정해야 했다. 2026-10-08에 같은 리포트 12건으로 후보를 비교했다.

## 결정
- 운영 `.env`의 `LLM_MODEL_PHASE2=codex:gpt-6-luna`. `codex:` 접두사는 API 대신 로컬 `codex exec`(ChatGPT 로그인 한도)로 실행한다. 코드 기본값은 API 모델 `gpt-6-luna`다.
- 재무 분석 응답(`ExtractionResult`)은 스키마가 커서, Claude 모델로 돌릴 때는 형식 강제(grammar) 대신 "스키마를 프롬프트에 넣고 JSON 글자를 받아 pydantic으로 검증"하는 경로(`constrained=False`)를 쓴다. 태깅과 비교는 형식 강제를 쓴다.
- 모델 이름이 공급자를 정하므로 되돌리기는 `.env`의 모델 이름만 바꾸면 된다.

## 버린 대안
- **Haiku(`claude-haiku-5-5`)로 분석**: 정확하지만 과거 실적·업종 KPI·이전 추정치 같은 재무 지표를 절반만 뽑았고, 형식이 12.5%(8회 중 1회꼴) 깨졌다.
- **API 과금 모델 그대로**: 사용자가 고른 리포트만 분석하므로 호출량이 적어, 로그인 한도로 충분하다.
- **Claude에서도 형식 강제**: 큰 스키마는 강제 경로에서 실패가 잦다.

## 결과
- Codex 로그인이 만료되거나 한도를 넘으면 분석·비교가 막힌다(`codex login`, 또는 `.env`를 API 모델로 바꾸고 웹앱 재시작).
- `CODEX_REASONING_EFFORT` 기본 `high`. `medium`은 빠르지만 재무 지표가 약 40% 적게 나온다.
- 저장된 분석은 원래 모델 정보(`llm_model`)를 유지하고 재사용된다. 모델을 바꿔도 일괄 재분석은 일어나지 않는다.
