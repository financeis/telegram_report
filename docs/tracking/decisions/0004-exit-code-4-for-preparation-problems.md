# 0004 — 다시 해도 안 풀리는 준비 문제는 종료 코드 4로 구분한다

## 배경
예전 분류 명령은 설정 누락을 예외로 처리해 종료 코드 1로 끝났다. 반복 실행 스크립트(`run-batches.ps1`)는 1을 "일시 실패"로 보고 되돌리기와 재시도를 세 번 한 뒤 "모두 실패"로 멈췄다. 키 누락이나 종목표 불일치는 몇 번을 다시 해도 풀리지 않는데, 운영자는 그 사이 원인을 알 수 없었다.

## 결정
- 종료 코드 4 = 준비 문제(설정 누락, codex CLI 없음, 종목표를 못 읽음, 종목표 버전 불일치, `stocks set-version --as-of`의 잘못된 날짜). `tag` 모든 하위 명령, `stocks set-version`, 앞으로 붙는 명령이 쓴다. stderr에 할 일을 한 줄로 찍는다.
- 분류 명령은 4로 끝날 때 어떤 행도 가져가지 않은 상태여야 한다(모든 확인을 가져가기 전에 한다).
- `tag inspect`·`tag reset-worker`는 `SUPABASE_DB_URL`만 요구한다(예전에는 모델 키도 요구했다). `tag escalate`는 시작할 때 재처리 모델의 키도 확인한다.
- `run-batches.ps1`은 4를 받으면 되돌리기·재시도 없이 바로 4로 멈추고 안내한다.
- `collect`만 예외로 설정 누락이 예전처럼 1이다.

## 버린 대안
- **1을 그대로 쓰고 메시지만 개선**: 스크립트가 재시도와 구분하지 못한다.
- **2를 쓰기**: 2는 argparse의 사용법 오류이자 `collect`의 "일부 실패"라 겹친다.

## 결과
- 새 명령도 준비 실패를 4로 끝내야 스크립트·예약 작업이 올바르게 멈춘다.
- `collect`의 1은 여전히 "설정 누락 또는 일시 장애"를 섞어서 뜻한다. 수집을 반복 실행하는 스크립트를 만들면 stderr의 `Config error:` 문구로 구분해야 한다.
