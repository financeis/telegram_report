# 0007 — 분류 LLM 동시 호출 2, 백필 배치 10

## 배경
백필(쌓인 `pending` 행 일괄 분류)을 빨리 끝내려고 동시 호출 수와 배치 크기를 키우고 싶어진다. 예전 `.env.example`의 기본값은 동시 호출 10이었다.

## 결정
- `MAX_CONCURRENT_LLM=2`가 운영 천장이다(코드 기본값도 2).
- 백필 배치는 10(`TAGGER_BATCH_SIZE_DEFAULT=10`, `run-batches.ps1 -BatchSize 10`).

근거:
- 실제 병목은 분당 요청 수가 아니라 분당 토큰 한도(TPM)다. gpt-5.4-mini 실측: 한도 200K TPM, 동시성 2에서 피크 ≈134K(67%). 동시성 10이면 한도를 넘어 429가 잦아지고 토큰 비용이 쌓이면서 처리량은 떨어진다.
- 동시성 2가 묶는 조건이라 배치를 100으로 키워도 총 처리량은 같다. 10이면 한 배치 실패 시 되돌릴 범위가 10건으로 작고, 배치마다 JSON 보고가 자주 찍혀 지켜보기 쉽다.

## 버린 대안
- **동시성 10**: 위 TPM 초과.
- **배치 100·200**: 처리량 이득 없이 실패 범위와 보고 간격만 커진다.

## 결과
- 위 TPM 수치는 gpt-5.4-mini(OpenAI) 기준이다. 태깅 모델이 2026-10-08부터 `claude-haiku-5-5`(Anthropic)라 한도 체계(입력·출력 토큰 한도 분리)와 행당 토큰(입력 ≈6K / 출력 ≈0.4K)이 다르다. 재검증 전까지 2를 유지한다.
- 올리려면 Anthropic Console(Limits)에서 Haiku 5.5의 토큰 한도를 확인하고, LangSmith 기록에서 토큰 추이를 검증한 뒤 한 단계씩(3 → 4) 시도한다.
- 백필 소요: 한 배치 ≈22~25초, 1,500회 ≈10시간이 약 15,000건의 실측 추산(gpt-5.4-mini). Haiku 5.5는 시험 실행에서 행당 2~11초였고, 첫 실운영 백필에서 다시 잰다.
