# 0011 — 유사 기업은 AI 사업 요약 카드와 임베딩으로 찾고, 목록은 요청할 때 계산하며, 등급은 백분위로 매긴다

## 배경
애널리스트 리포트는 대형주 위주라 코스닥 중소형주는 리포트가 거의 없다. 사용자는 어떤 테마가 오를 때 비슷한 사업을 하면서 증권사 리포트가 없고 아직 덜 오른 회사를 찾으려 한다(예: 제주반도체가 급등했을 때 같은 레거시 메모리 사업을 하는 회사). 종목표의 업종(산업명 대·중)으로는 이런 묶음이 안 잡힌다 — 제주반도체는 `비메모리_팹리스`로 분류돼 메모리 회사들과 묶이지 않는다. 사업보고서의 글로 회사를 비교하되, 무엇을 비교할지, 언제 계산할지, 비슷함을 어떤 기준으로 나눌지, 어떻게 저장할지를 정해야 했다.

## 결정
- 회사마다 사업보고서의 사업 내용을 AI가 정해진 모양의 사업 요약 카드(프로필: 틈새 업종, 요약, 가치사슬 역할, 사업부문, 제품, 키워드, 적용처, 고객사·경쟁사)로 만든다(사용자 선택). 입력 글에 없는 용어는 버린다.
- 회사 하나와 사업부문마다 임베딩을 만든다. 유사도는 임베딩의 코사인이다.
- 피어 목록은 미리 저장하지 않고, 요청할 때 DB 함수 두 개(회사 임베딩·부문 임베딩 정확 탐색)로 계산한다.
- 비슷함의 등급은 그 빌드의 모든 쌍 코사인 분포로 만든 백분위표로 매긴다(99.5 / 98 / 95 백분위).
- 임베딩은 1536차원으로 고정하고(`text-embedding-3-large`·`-small` 모두 1536으로 낼 수 있다), 임베딩 모델마다 따로 저장한다. 프로필은 (회계연도, 프로필 버전, 종목코드)로 저장하고, 동의어 정규화는 빌드 때 한다.

## 버린 대안
- **사업보고서 원문을 그대로 비교**: 업종 공통 문구(산업의 특성·시장 규모·성장성)가 유사도를 좌우하고, 왜 비슷한지를 보여 줄 수 없고, 테마 검색에 약하다.
- **미리 계산한 피어 표**(빌드마다 회사별 상위 목록 저장): 빌드마다 회사 수 × 목록 길이만큼 행이 쌓이고, 화면의 부문 선택과 테마 검색은 어차피 따로 계산해야 한다. 상장사 전체(코스피·코스닥)라도 DB 안 정확 탐색이 충분히 빠른 규모다.
- **고정 코사인 문턱**: 코사인 값의 크기는 임베딩 모델과 연도마다 달라, 같은 문턱이 같은 뜻을 갖지 않는다.
- **모델에 맞춘 차원**: 시험 실행에서 small·large 모델을 바꿔 볼 때마다 표 구조(마이그레이션)를 바꿔야 한다.
- **임베딩을 프로필 행의 한 칸으로**: 임베딩 모델을 바꾸면 이미 공개된 빌드가 쓰는 임베딩을 덮어쓴다.
- **동의어 정규화를 AI 추출 때**: 동의어표를 고칠 때마다 비싼 AI 추출을 다시 해야 한다.

## 결과
- 유사 기업 탭은 AI를 부르지 않는다(DB 함수 두 번과 읽기). 테마 검색만 새 질의마다 임베딩 하나를 부른다.
- 백분위표와 용어표는 공개 빌드(`done`)를 만들 때마다 새로 계산되고, 화면은 가장 최근 공개 빌드만 쓴다. 95 백분위 아래는 목록에 나오지 않는다.
- 임베딩 모델을 바꾸면 임베딩만 다시 만든다(AI 추출 없음). 1536차원을 낼 수 없는 모델은 마이그레이션 없이 쓸 수 없다.
- 프롬프트·응답 모양·입력 조립을 바꾸면 프로필 버전을 올려 모든 회사를 다시 추출한다(AI 비용).
- 같은 (회계연도, 프로필 버전)의 빌드들은 프로필 행을 함께 쓴다. 다음 빌드가 다시 추출한 회사의 프로필은 지금 공개된 빌드의 화면에도 바로 바뀌어 보인다.
- 지난 빌드의 피어 목록은 저장돼 있지 않아 그대로 다시 보여 줄 수 없다.
