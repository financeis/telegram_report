# 0005 — 웹 기능은 각자 준비하고, 준비 실패는 그 기능만 멈춘다

## 배경
예전 웹앱은 서버 전체의 준비(설정·DB 연결·종목표)가 한 번에 묶여 있어, 하나가 실패하면 모든 주소가 막혔다. 분석 모델 키 누락도 이유 없는 일반 503이었다. 앞으로 붙일 수급 기능 등은 외부 키를 쓰고, 그 키는 만료될 수 있다. 그 기능 하나 때문에 리포트 보기·검토까지 막히면 안 된다.

## 결정
- 각 기능은 처음 쓰일 때 준비하고, 실패하면 `NotReady(<한국어 기능 이름>, <고정 이유>)`를 낸다. 웹 조립부가 이것을 그 주소의 503 `"<기능 이름> 기능을 지금 쓸 수 없습니다: <이유>"`로 바꾼다. `/api/health`와 다른 기능은 정상이다.
- 실패를 기억하지 않는다. 다음 요청 때 다시 준비하므로, 빠진 파일을 채우거나 `.env`에 빠진 값을 넣으면 서버를 다시 켜지 않아도 회복한다.
- `.env`는 준비할 때마다 다시 읽되 이미 있는 값은 덮어쓰지 않는다(예전 동작 유지). 그래서 이미 있던 값을 바꾼 것은 다시 켜야 반영된다.
- 모델 키는 실제 AI 호출 직전에만 확인한다. 키가 없어도 목록·재사용·검토는 동작한다.
- 준비가 끝난 뒤의 예기치 못한 오류(DB 일시 장애)는 일반 503 문구를 그대로 쓴다.

## 버린 대안
- **서버 시작 때 전체 준비(예전 방식)**: 한 기능의 고장이 전체를 막는다.
- **실패를 기억하고 재시작으로만 회복**: 운영자가 원인을 고쳐도 서버를 다시 켜야 한다.
- **`.env`를 매번 덮어쓰며 다시 읽기**: 프로세스가 받은 환경 변수(스크립트가 넘긴 값)를 `.env`가 조용히 이긴다.

## 결과
- 새 기능도 준비 실패를 같은 방식으로 내야 하고, 고정 한국어 기능 이름을 정해야 한다. 이유 문구에 파일 경로·키 값·오류 추적을 넣지 않는다.
- 다른 기능의 공개 창구에서 온 `NotReady`는 바꾸지 않고 올린다(예: 커버리지 화면에서 "리포트 기능을 지금 쓸 수 없습니다").
- 준비 실패가 기억되지 않으므로, 설정이 빠진 채로 계속 요청이 오면 요청마다 준비를 다시 시도한다(가벼운 확인뿐이라 부담은 작다).
