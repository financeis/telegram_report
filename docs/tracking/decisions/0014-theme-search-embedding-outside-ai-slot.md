# 0014 — 테마 검색의 질의 임베딩은 `analysis.ai_slot()` 밖에서, 유사 기업 기능의 동시 2개 자리로 한다

## 배경
웹 서버 안의 AI 호출은 모두 `analysis.ai_slot()`(분석·비교를 합쳐 동시 2개) 안에서, `analysis.phase2_llm()`이 준 모델로 한다는 규칙이 있었다. 테마 검색은 새 질의마다 임베딩 호출 하나(1초 안팎)가 필요하다. 재무 분석 호출은 한 번에 1~2분(한도 180초) 걸린다.

## 결정
- 질의 임베딩은 유사 기업 기능의 자체 자리(프로세스 안 동시 2개)에서, 호출 시간 한도 15초로 부른다. `analysis.ai_slot()`을 쓰지 않는다.
- 모델은 공개 빌드에 기록된 임베딩 모델(1536차원)이고 키는 `OPENAI_API_KEY`다. 키가 없으면 테마 검색 주소만 `유사 기업 기능을 지금 쓸 수 없습니다: OPENAI_API_KEY가 설정되지 않았습니다`로 막힌다.
- 같은 (모델, 정규화한 질의)는 프로세스 안 캐시(최근 256개)로 답한다.

## 버린 대안
- **`ai_slot()`을 같이 쓰기**: 분석 두 건이 자리를 잡고 있으면 1초도 안 걸릴 검색이 몇 분을 기다린다.
- **`phase2_llm()`의 모델 쓰기**: 분석 모델(`codex:gpt-6-luna` 등)은 임베딩을 만들 수 없고, 질의 임베딩은 빌드에 저장된 임베딩과 같은 모델이어야 비교된다.

## 결과
- 웹 서버의 AI 호출은 동시에 최대 4개까지 돈다(분석·비교 2 + 질의 임베딩 2). 임베딩은 토큰이 아주 적다.
- 분석이 codex(로그인 한도)로 돌아도 테마 검색에는 `OPENAI_API_KEY`가 있어야 한다.
- 예외는 테마 검색의 질의 임베딩 하나다. 다른 새 웹 AI 호출은 여전히 `ai_slot()` 안에서 한다 — 예외를 넓히면 웹 서버 전체 동시 호출 2라는 한도가 사라진다.
