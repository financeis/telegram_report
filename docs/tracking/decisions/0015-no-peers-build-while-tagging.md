# 0015 — 분류 작업이 돌고 있으면 유사도 계산을 시작하지 않는다(한쪽만 자동)

## 배경
AI 동시 호출 2가 운영 천장이다(실제 병목은 공급자의 분당 토큰 한도). 유사도 계산(`peers build`)은 회사마다 AI를 동시 2개로 부르며 몇 시간 걸린다. 분류 백필도 동시 2개로 몇 시간 돈다. 둘이 겹치면 4개가 되어 429가 잦아지고 토큰 비용만 는다.

## 결정
- `peers build`는 준비 확인을 마친 뒤, 리포트 창구의 `tagging_in_progress()`(최근 30분 안에 잠긴 `processing` 행이 있는지 — 행을 읽지 않는 개수 조회)가 참이면 시작하지 않는다. 문구 `분류 작업이 진행 중이라 유사도 계산을 시작하지 않았습니다. 분류가 끝난 뒤 다시 실행하세요.`, 종료 코드 1.
- 반대 방향(빌드 중에 분류를 시작)은 자동으로 막지 않는다. "유사도 계산 중엔 분류 백필을 시작하지 않는다"는 운영 규칙으로 둔다.

## 버린 대안
- **양쪽 다 자동으로 막기**: 분류기는 `core`·`domain`만 쓸 수 있어 유사 기업 기능의 빌드 기록을 읽을 수 없다. 두 쪽이 같이 보는 잠금 장치를 새로 만들어야 한다.
- **종료 코드 4**: 4는 "다시 실행해도 저절로 안 풀리는 준비 문제"다. 분류가 끝나면 저절로 풀리므로 1이다.
- **겹쳐 돌리기**: 위의 분당 토큰 한도 초과.

## 결과
- 이 확인은 정상 `tag run`이 가져간 행만 본다. 반복 분류 스크립트의 배치 사이(다음 `tag run` 프로세스가 뜨는 몇 초), `tag run --row-ids`, `tag escalate`, `tag run --dry-run`은 행을 `processing`으로 바꾸지 않아 보이지 않는다. 백필 창이 열려 있으면 사람이 빌드를 시작하지 않는다.
- 이 확인은 분류기의 잠금 표시(`tagging_status='processing'`과 `tagging_locked_at`)에 기댄다. 분류기의 가져가기 방식을 바꾸면 이 확인도 함께 바꿔야 한다.
- 확인이 리포트 창구를 거치므로 `peers build`는 실행될 때 FastAPI를 불러온다(웹 패키지가 필요하다).
